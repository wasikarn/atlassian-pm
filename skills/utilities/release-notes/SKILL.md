# /release-notes

**Role:** PM — Release Documentation
**Output:** Confluence release notes page under the project space

## Dynamic Context

- **Today:** !`date +%Y-%m-%d`
- **Project:** @.claude/project-config.json → `confluence.space_key`, `jira.project_key`

## Context Object

| Phase | Adds to Context |
| --- | --- |
| 1. Fetch Version | `version_name`, `version_description`, `release_date` |
| 2. Fetch Issues | `features[]`, `bugfixes[]`, `chores[]`, `total_sp` |
| 3. Draft | `page_draft` (ADF) |
| 4. Review | User-approved draft |
| 5. Publish | `confluence_page_url` |
| 6. Summary | Done |

---

## Phase 1 — Fetch Fix Version 🟢 AUTO

1. If `--version` provided → use it.
2. Else → `jira_get_project_versions(project_key="{{PROJECT_KEY}}")` and display released/unreleased versions for user to select.

```python
jira_get_project_versions(project_key="{{PROJECT_KEY}}")
```

Display version details:

```
## Fix Version: [version_name]

**Description:** [description]
**Release Date:** [date]
**Status:** [Released / Unreleased]
```

---

## Phase 2 — Fetch Issues in Version 🟢 AUTO

```python
jira_search(
    jql="project = {{PROJECT_KEY}} AND fixVersion = '[version_name]' AND resolution = Done",
    fields="summary,issuetype,labels,assignee,customfield_10016,parent",
    limit=100
)
```

Group issues:

| Group | Criteria |
| --- | --- |
| **Features** | issuetype = Story (or Epic children) |
| **Bug Fixes** | issuetype = Task AND summary starts with "[Bug]" |
| **Improvements** | issuetype = Task AND labels contains "tech-debt" or "chore" |
| **Other** | Everything else |

Display summary:

```
## Issues in [version_name] ([N] total, [SP] SP)

Features:     [N] issues
Bug Fixes:    [N] issues
Improvements: [N] issues
Other:        [N] issues
```

---

## Phase 3 — Draft Release Notes 🟡 REVIEW

Generate ADF page content for Confluence.

**Page title:** `Release Notes — [version_name] ([date])`

**Page structure:**

```
# Release Notes — [version_name]

📅 Release Date: [date]
📦 Version: [version_name]
📊 [N] changes · [SP] story points

---

## 🚀 New Features

| Feature | Summary | Team |
|---------|---------|------|
| [KEY]   | [summary] | [assignee] |
...

## 🐛 Bug Fixes

| Bug | Summary | Severity |
|-----|---------|----------|
| [KEY] | [summary] | [P1/P2/P3 from label] |
...

## 🔧 Improvements & Maintenance

| Task | Summary | Type |
|------|---------|------|
| [KEY] | [summary] | [tech-debt/chore] |
...

---

## What's Changed

[Narrative paragraph summarizing the release in plain language for stakeholders.
Focus on user-facing impact. Avoid technical jargon.]

---

*Generated by atlassian-pm on [today's date]*
```

Display draft for review. 🟡 REVIEW — user can request edits before publishing.

---

## Phase 4 — Publish to Confluence 🟢 AUTO (after approval)

If `--dry-run`: display full draft and stop.

```python
confluence_create_page(
    space_key="{{PROJECT_KEY}}",
    title="Release Notes — [version_name] ([date])",
    body=<ADF content>,
    parent_id=<release-notes-parent-page-id if exists>
)
```

If parent page not found → create at space root.

---

## Phase 5 — Link Back to Jira Version 🟢 AUTO

Add remote link from Jira Fix Version to Confluence page:

```python
# Add comment to each Story/Epic in the version with the release notes URL
jira_add_comment(
    issue_key="[first_story_key]",
    comment=f"Release notes published: [confluence_page_url]"
)
```

## Examples

### ✅ Good

```text
/release-notes --version v2.3.0 --dry-run               # preview draft before publishing — always do this first
/release-notes --version v2.3.0                          # publish release notes for a specific fix version
/release-notes --version v2.3.0 --epic {{PROJECT_KEY}}-10            # scope notes to a specific epic within the version
/release-notes --dry-run                                 # interactive version selection + preview (no publish)
```

### ❌ Bad

```text
/release-notes                                           # skips --dry-run — publishes immediately without preview
/release-notes --version v2.3.0                          # valid flags, but Fix Version "v2.3.0" not created in Jira yet —
                                                         # Phase 1 fetch will return empty; create the version first
/release-notes --version "Sprint 12"                     # sprint name is not a Fix Version — use /close-sprint for
                                                         # sprint review output; release-notes requires a Fix Version key
/release-notes --dry-run                                 # using to replace /close-sprint sprint review reporting —
                                                         # release-notes groups by Fix Version, not sprint completion
```

**Common mistakes:**

- Publishing without `--dry-run` first — always preview the draft so stakeholders do not receive a malformed page; Phase 3 is marked REVIEW for this reason
- Running before creating the Fix Version in Jira — the JQL in Phase 2 queries `fixVersion = '<name>'` and returns zero issues if the version does not exist
- Using a sprint name as the `--version` value — Fix Version keys follow the project versioning scheme (e.g. `v2.3.0`), not sprint names; use `/close-sprint` for sprint-based summaries
- Using this skill instead of `/close-sprint` for sprint review reporting — `/close-sprint` generates the retrospective and sprint review; `/release-notes` generates stakeholder-facing release documentation tied to a Fix Version
